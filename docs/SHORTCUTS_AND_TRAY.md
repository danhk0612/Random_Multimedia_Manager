# 단축키 및 트레이 정책

이 문서는 T14가 확정한 Windows 생명주기 정책의 단일 상세 기준이다. T15는 트레이·창 동작을, T16은 빠른 숨김·음소거·정상 종료를 이 계약대로 구현한다. 데이터·삭제 정책은 docs/DATA_AND_RANDOM_POLICY.md를 우선하며 이 문서는 그 의미를 바꾸지 않는다.

## 1. 기본 창·트레이 정책

- 앱은 시작 시 메인 창을 정상 표시한다. 시작부터 트레이 전용으로 숨기는 기본값은 두지 않는다.
- 메인 창 최소화는 일반 최소화로 처리하며 작업표시줄에 유지한다. 최소화만으로 트레이 전용 상태로 바꾸지 않는다.
- 메인 창의 일반 닫기(X)는 트레이로 숨김을 기본 동작으로 한다. 감상 창의 닫기는 기존처럼 해당 감상 세션을 정상 종료하며 트레이 숨김으로 대체하지 않는다.
- 트레이 아이콘은 앱 실행 중 항상 표시한다. Quick Hide도 트레이 아이콘을 숨기지 않는다. 숨김 중에도 복원 경로를 잃지 않기 위해서다.
- 트레이 메뉴의 최소 범위는 열기/복원, 모두 숨기기/복원, 종료다. 재생·이전/다음·즐겨찾기 등 미확정 원격 조작 메뉴는 추가하지 않는다.
- 트레이 아이콘 더블클릭은 열기/복원과 동일하다. 이미 표시 중이면 메인 창을 전면 활성화한다.
- 일반 닫기 동작을 실제 종료로 바꾸는 설정 UI는 T15에서 제공할 수 있으나 기본값은 트레이 숨김이다. Windows 자동 시작은 비범위다.

## 2. Quick Hide 기본값

- 기본 전역 키는 Ctrl+Shift+H다. 기본 활성화한다. 등록 실패나 충돌 시 앱은 실행을 계속하고 해당 기능만 비활성 상태로 명확히 표시한다. 다른 키를 자동 탈취하거나 임의 대체하지 않는다.
- Quick Hide는 앱이 소유한 모든 보이는 창을 즉시 숨긴다. 메인 창, 감상 창, 전체화면, 검증/보조 창과 열려 있는 앱 소유 대화상자가 대상이다.
- Quick Hide는 영상만 앱 수준으로 음소거한다. 만화에는 소리가 없으므로 별도 pause 상태를 만들지 않는다.
- Quick Hide는 재생을 일시정지하지 않는다. 영상은 재생 위치가 계속 진행될 수 있다. 숨김은 감상 기록 확정이나 checkpoint 강제 저장 명령이 아니다.
- 숨김 직전 각 창의 Visibility/WindowState/전체화면 여부와 각 활성 영상의 앱 mute 상태를 메모리에 캡처한다. 세션/창 복원 정보는 영속하지 않는다.
- 복원은 같은 전역 키 또는 트레이의 열기/복원·모두 복원으로 수행한다. 숨기기 전 보였던 앱 창만 원래 표시 상태로 복원한다.
- 복원 시 앱이 Quick Hide 때문에 강제로 켠 mute만 원래 앱 mute 값으로 되돌린다. 사용자가 원래 음소거한 영상은 계속 음소거다.
- 외부 자동 음소거 프로그램이나 Windows/드라이버가 변경한 시스템 음소거 상태를 앱이 추정해 해제하지 않는다. 앱은 자신이 제어한 미디어 mute만 복원한다.
- Quick Hide 중 새 창·대화상자를 생성하는 사용자 명령은 받지 않는다. 이미 진행 중인 작업이 완료되어 앱 소유 창/대화상자를 만들려 하면 Hidden 상태에 편입해 보이지 않게 유지하고 복원 시 표시한다.
- Quick Hide 반복 입력은 멱등 처리한다. Hidden이면 복원, Visible이면 숨김이며 중간 전이 중 추가 입력은 한 번의 최종 상태 요청으로 합쳐 중복 Hide/Show를 실행하지 않는다.

## 3. 정상 종료 정책

종료 진입점은 트레이 종료, 향후 T16 빠른 종료 키, 그리고 명시적 앱 종료 명령이다. 일반 메인 X의 기본 트레이 숨김과 구분한다.

빠른 정상 종료는 다음 순서를 따른다.

1. 즉시 가리기: 모든 앱 표시를 숨기고 활성 영상에 앱 mute를 적용한다. 이 단계는 데이터 변경을 하지 않는다.
2. Closing 진입: 새 창/대화상자/새 랜덤·탐색·checkpoint·설정 저장 등 신규 사용자 명령을 거부한다. 중복 종료 요청은 같은 종료 작업을 재사용한다.
3. Opening 정리: 준비 중 미디어가 있으면 기존 취소 계약으로 준비를 취소하고 늦은 결과를 폐기·해제한다. 저장 단계에 들어간 작업은 취소해 되돌리지 않는다.
4. T12 경계 대기: 삭제가 진행 중이면 새 종료 작업과 경쟁시키지 않고 T12의 직렬화 경계가 현재 삭제 결과를 확정할 때까지 기다린다. Unknown/격리 상태를 성공으로 추정하지 않는다.
5. 현재 방문 정상 저장: Active Pending은 기존 SessionCoordinator.LeaveAsync 계약으로 최종 진행과 감상 기록을 저장한다. Quick Hide는 SuppressHistory를 만들지 않으며 기존 이번 기록 제외 값만 존중한다.
6. 리소스 해제: 세션 저장 성공 확인 후 현재 만화/영상 리소스와 보조 창 리소스를 정상 해제한다.
7. DB/앱 종료: 진행 중인 직렬 DB 작업이 끝난 것을 확인하고 전역 키를 해제한 뒤 트레이 아이콘을 제거하고 WPF 종료를 완료한다.

강제 Kill, 임의 timeout 뒤 강제 종료, Pending 자동 폐기, 삭제 성공 추정은 사용하지 않는다.

## 4. 저장·해제 실패 정책

- 방문 저장이 SaveFailed면 종료를 완료하지 않는다. 앱은 계속 숨김+앱 음소거 상태를 유지하며 데이터와 Pending을 보존한다.
- CommitUnknown도 종료하지 않는다. 저장 성공/실패를 추정하지 않고 기존 FrozenCommit을 유지한다.
- 사용자는 트레이 메뉴의 열기/복원으로 오류 UI에 접근해 기존 재시도 또는 감상 복귀 흐름을 사용한다. 오류가 해결되기 전 종료 재요청은 같은 정상 저장 절차를 다시 시도한다.
- 미디어 해제 실패도 프로세스를 강제로 종료하지 않는다. 가능한 창은 숨긴 채 오류 상태를 유지하고 트레이 복원 경로를 제공한다. 이미 저장된 감상 기록은 되돌리지 않는다.
- DB 자체가 더 이상 사용할 수 없는 종료 오류라면 성공처럼 닫지 않는다. 오류를 표시할 수 있도록 복원 경로를 유지한다.
- 앱 충돌/OS 강제 종료처럼 정상 종료 절차를 거치지 못한 경우에는 T02 계약대로 메모리 Pending을 재시작 시 추정 복구하지 않는다.

## 5. 생명주기 상태

앱 수준 상태는 구현 시 과도한 새 프레임워크 없이 다음 의미를 보존한다.

| 상태 | 의미 | 허용되는 핵심 입력 |
|---|---|---|
| Visible | 앱의 정상 표시 상태 | 일반 UI, Hide, Exit |
| Hidden | Quick Hide 또는 트레이 숨김으로 앱 표시가 없음 | Restore, Exit |
| Closing | 정상 종료 절차 진행 중 | 동일 Exit 재요청, 필요한 취소/저장 복구만 |
| ExitBlocked | SaveFailed/CommitUnknown/해제 실패 등으로 종료가 중단됨 | Restore, 저장 재시도/복귀, Exit 재시도 |
| Exited | 리소스/키/트레이 해제 후 종료 | 없음 |

감상 세션의 Opening/Active/SaveFailed와 T12의 Deleting/Quarantined/Recovery는 별도 하위 상태다. 앱 생명주기는 이를 덮어쓰지 않고 아래 연결 규칙만 적용한다.

## 6. 세션·삭제 상태별 Hide/Exit 전이

| 하위 상태 | Quick Hide | 정상 종료 |
|---|---|---|
| 감상 없음 | 창 숨김/복원만 | 리소스/DB 정리 후 종료 |
| Opening | 표시 숨김+앱 mute; 준비는 계속 가능 | 준비 취소 요청 후 소유 리소스 해제, 현재 기존 방문이 있으면 그 방문을 정상 저장 |
| Active | 표시 숨김+앱 mute; Pending 유지, 기록 확정 없음 | 최종 위치 캡처→기존 LeaveAsync 저장→해제 |
| SaveFailed / CommitUnknown | 숨김 가능, FrozenCommit 유지 | 종료 차단. 성공/실패를 추정하지 않음 |
| checkpoint/DB 쓰기 중 | 숨김은 가능 | 이미 입장한 짧은 작업 완료 후 종료 절차 계속. 신규 checkpoint는 차단 |
| T12 Deleting | 표시 숨김 가능 | T12 작업과 경쟁하지 않고 결과 경계까지 대기 |
| T12 Failed/Cancelled | 기존 방문/억제 보존 | 삭제 상태 정리 후 일반 Active 규칙으로 종료 |
| T12 Unknown/격리 | 숨김 가능 | 삭제 성공을 추정하지 않음. 현재 Pending의 PathKey가 격리되면 Leave를 강행하지 않고 ExitBlocked. 현재 방문과 무관한 durable 격리는 저널을 보존하고 진행 중 작업이 끝난 뒤 종료 가능 |
| T12 Succeeded + DB 정리 중 | 숨김 가능 | AppliedDeletion까지 완료한 뒤 종료 |
| 전체화면 | 전체화면 창 포함 숨김 | 숨김 후 정상 종료; 복원 시 종료가 취소/차단된 경우 이전 전체화면 상태 복원 |

### T12 통합 대조 결과

PR #16의 SessionCoordinator.Deletion, DeletionService, ViewingWindow와 대조했다. DB 스키마·삭제 저널·기록 정책 변경은 없다.

- 삭제 대기는 SessionPhase.Deleting만 감시하지 않는다. ViewingWindow의 실행 중 명령 Task와 DeletionService.Pending을 함께 관찰한다. 준비/저널/OS 결과/DB 정리/재열기를 포함한 명령이 끝난 뒤 판단한다. T15/T16은 이를 기다리는 최소 연결점만 추가한다.
- 현재 Pending 경로가 Unknown/격리이면 기존 LeaveAsync의 CommitUnknown을 존중해 ExitBlocked로 남긴다. 복원 후 기존 사용자 확인/복구 UI로 해결하며 Pending을 폐기하지 않는다.
- 현재 방문과 무관한 Prepared/Unknown durable 복구 항목은 진행 중 명령이 없고 저널·격리가 보존되는 경우 종료를 허용한다. 다음 시작의 기존 복구 절차를 사용하며 OS 삭제를 자동 재실행하지 않는다. 손상 저널에 대한 전역 차단도 우회하지 않는다.
- Succeeded는 현재 방문 tombstone과 DB 정리가 별개다. AppliedDeletion 및 저널 정리 완료 전 오류가 있으면 종료를 차단하고 기존 복구를 재시도한다. OS 삭제를 다시 호출하지 않는다.
- Failed/Cancelled는 저널 정리와 같은 방문 재열기 작업이 끝난 뒤 기존 Pending/억제를 정상 저장한다. 재열기 실패 시에도 보존된 진행과 방문을 임의 삭제하지 않는다.
- 삭제가 해제한 미디어를 종료 경로에서 중복 해제하지 않는다. 아직 소유한 리소스만 해제하며 Completed 결과라도 Error/해제 오류를 별도 확인한다. 저장 완료를 리소스 해제 성공으로 추정하지 않는다.

## 7. T15 구현 경계

T15는 다음만 구현한다.

- 트레이 아이콘과 최소 메뉴(열기/복원, 모두 숨기기/복원, 종료)
- 메인 창 X 기본 트레이 숨김, 일반 최소화, 시작 시 표시
- 트레이/창 표시 상태의 단일 조정 경로와 중복 요청 방지
- 실제 동작하는 트레이 정상 종료: 기존 비동기 감상 닫기/Leave와 진행 중 명령 대기를 연결하는 최소 조정 경로. 저장/해제 실패 시 앱과 복원 경로를 보존한다. Application.Shutdown을 먼저 호출하거나 종료 메뉴를 무동작으로 두지 않는다.
- 단계적 구현: T15의 열기/복원 및 메인 X 숨김은 일반 창 동작이다. 모든 창 숨김+음소거 메뉴는 T16에서 활성화하며 그 전에는 미구현 상태로 비활성 표시한다. 음소거 없는 동작을 Quick Hide로 표시하지 않는다.

T15의 일반 정상 종료에 즉시 숨김+음소거를 결합하는 작업은 T16이다. T15에서 전역 키, 빠른 종료 전체 순서, 삭제 계약, DB 스키마, 재생/기록 정책을 구현하지 않는다.

### T15 구현 연결점

AppLifecycle이 일반 종료를 조정하며 ViewingWindow.RequestCloseAsync의 결과를 기다린다. UI 명령 Task와 SessionCoordinator.WhenIdleAsync를 함께 관찰한다. DeletionService.HasIncompleteSuccess는 Pending의 Succeeded뿐 아니라 성공 결과 저널 저장 실패로 Prepared가 남은 현재 프로세스의 성공도 포함한다. 삭제 계약/저널 형식은 유지한다. 해제 실패를 기억하여 이후 NoOp 종료로 우회하지 않는다. 자동/사용자 검증과 제한은 docs/T15_LIFECYCLE_VALIDATION.md를 따른다.

## 8. T16 구현 경계 및 검증

T16은 이 문서의 Quick Hide와 정상 종료 순서를 구현한다. 구현은 기존 SessionCoordinator/ViewingWindow/T12 API를 재사용하고 필요한 최소 생명주기 조정만 추가한다.

필수 Windows 검증:

- 메인/감상/전체화면/보조 창이 함께 있을 때 Hide 후 모두 보이지 않고 Restore 시 이전 표시 상태 복원
- 영상 재생 중 Hide가 앱 mute만 적용하고 pause하지 않으며 복원 시 원래 앱 mute 상태 복원
- 원래 mute/일시정지된 영상이 복원 후 그대로 유지
- 외부 음소거 변경을 앱이 임의로 해제하지 않음
- Ctrl+Shift+H 등록 성공/충돌/해제와 반복 입력
- Hidden 중 새 앱 창·대화상자가 노출되지 않음
- Opening 중 Exit, Active Pending Exit, SaveFailed/CommitUnknown Exit 차단·복원·재시도
- checkpoint/DB 작업 중 Exit 직렬화
- T12 삭제 진행/실패/취소/Unknown/Succeeded 경계와 Exit의 결합
- 중복 Exit가 저장/해제를 중복 실행하지 않음
- 정상 Exit 뒤 파일 잠금, 전역 키, 트레이 아이콘, 앱 프로세스가 남지 않음

## 9. 비범위
