## 해석 및 설계 경계

- 감상 기본 처리는 성공적으로 열린 미디어에 적용한다. 열기 실패는 기존 R08에 따라 감상으로 기록하지 않는다. 기록 확정 시점은 항목을 벗어날 때이며, 이번 기록 제외는 1회만 억제한다.
- 이름 변경도 경로가 달라진 경우 이전 상태를 새 항목에 자동 승계하지 않는 방향으로 설계한다. 자동 fingerprint 병합은 초기 구현하지 않는다.
- 분류별 상태 분리는 물리 파일 복제를 뜻하지 않는다. 실제 파일을 삭제하면 다른 분류에서도 파일이 사라진다. 같은 물리 경로의 삭제 후 존재 상태/기록 정리 범위는 T02에서 명시한다.
- 휴지통 실패 시 임의 영구 삭제로 전환하지 않는다. 실제 삭제 실패 시 기존 기록을 제거하지 않는다.
- 빠른 종료도 기록 제외 명령이 아니므로 D02의 기본 감상 원칙을 적용하는 방향으로 설계한다. 숨김만 수행한 경우에는 감상이 계속되므로 기록을 확정하지 않는다.
- 숨김 후 종료는 종료 기능의 순서다. 별도의 숨김/복원 기능과 혼동하지 않는다. 강제 Kill이나 일정 시간 후 강제 종료를 기본으로 추가하지 않는다.
- 위임은 기존 요구사항 안의 세부값/동작 결정에 한정한다. 아래 후순위 기능을 새로 구현할 권한을 뜻하지 않는다.
- Windows 세부 버전 및 네이티브 패키지 포함 가능 여부는 T18에서 검증한다. exe/압축 배포 승인은 단일 exe에 모든 파일을 포함할 수 있다는 보장이 아니다.

## 담당자가 다음에 확정할 사항

T02: 7일 경계/0일/후보 소진, 분류별 식별과 경로 변경, 삭제된 물리 파일의 각 분류 기록 정리, 재감상/전환 실패 상태표, 스키마·설정 저장·공통 계약.
T14: 키/트레이 기본값, 숨김·복원 상태표, 먼저 숨김/음소거 후 정상 종료 순서와 저장/해제 실패 처리.
이 항목은 사용자 재질문이 필수인 차단 상태가 아니다. 위임 범위 안에서 결정하고 문서화하되, 요구사항 충돌이나 범위 확대가 필요할 때만 확인한다.
